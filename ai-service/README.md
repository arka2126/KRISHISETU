# KrishiSetu AI Market Intelligence Service

A Python/FastAPI microservice providing price prediction, forecasting, trend and
anomaly detection, market comparison, and AI-generated recommendations for the
KrishiSetu marketplace. It is called by the Node.js backend (`backend/services/aiServiceClient.js`)
via `/api/ai/*` — the frontend never talks to this service directly.

## Data honesty

This service ships **with no real market-data API credentials**. Every response's
`source`/`basis` field says so explicitly:

- Prices, arrivals, weather → `"source": "MOCK_DATA"` (synthetic but seasonally
  realistic, generated by `app/data/adapters.py::MockMarketDataProvider`).
- `"basis": "OBSERVED_DATA"` = computed from that historical series, not a model output.
- `"basis": "AI_PREDICTION"` = a trained model's output, always with a computed
  confidence interval (never a bare number).
- `"basis": "AI_INSIGHT"` = the recommendation layer, built by combining the above —
  every sentence it produces cites a number that's also present in the payload.

Real adapters (`AgmarknetAdapter`, `OpenWeatherAdapter` in `app/data/adapters.py`)
are stubbed with a documented `NotImplementedError` rather than faking a live
integration — see that file's docstrings for exactly what's needed to wire a real
one in, and `.env.example` for the credential variables the factory functions
(`get_market_adapter`, `get_weather_adapter`) look for.

## Setup

```bash
cd ai-service
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env

python train_all.py             # pre-trains a price model for every demo commodity/market
uvicorn app.main:app --reload --port 8001
```

Interactive API docs: http://localhost:8001/docs

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | service + data source status |
| GET | `/api/v1/model-status` | which commodity/market models are trained, with metrics |
| POST | `/api/v1/train` | train (or retrain) a price model for one commodity/market |
| POST | `/api/v1/predict-price` | next-day (or +2/+3 day) point prediction + interval |
| POST | `/api/v1/forecast` | 7/30-day (configurable) Holt-Winters forecast |
| POST | `/api/v1/trend-analysis` | rising/falling/stable/unusual classification |
| POST | `/api/v1/anomaly-detection` | z-score + Isolation Forest anomaly list |
| POST | `/api/v1/market-comparison` | side-by-side markets for one commodity |
| POST | `/api/v1/demand-supply` | arrivals trend + price/arrivals correlation |
| POST | `/api/v1/recommendations` | templated, data-grounded recommendation text |
| POST | `/api/v1/market-insights` | one bundled call (current + trend + anomalies + prediction) for the dashboard |

## Pipeline

```
Raw (mock or real) data
  -> validate_raw()        required columns, positive prices
  -> clean()                de-dupe, sort, parse dates
  -> handle_missing_values() forward/back fill short gaps
  -> detect_and_clip_outliers() IQR-based, flags kept for anomaly detection
  -> engineer_features()    lags, rolling mean/std, seasonal encodings
  -> train/predict
```
See `app/pipeline/preprocessing.py`.

## Model choices (and why)

- **Price prediction**: RandomForestRegressor vs XGBoost, trained on a time-based
  (non-shuffled) 85/15 split, whichever scores lower MAPE on the held-out tail is
  kept and refit on all data (`app/models/price_predictor.py`). Confidence interval
  = ±1.96·σ where σ is the real standard deviation across the RandomForest's
  individual trees (or backtested RMSE for XGBoost) — not an arbitrary number.
- **Forecasting**: Holt-Winters exponential smoothing (`statsmodels`), not Prophet —
  documented in `app/models/forecaster.py` why Prophet's heavier toolchain isn't
  justified for a single mild yearly cycle, and how to swap it in later.
- **Anomaly detection**: rolling z-score (univariate, price & arrivals) *and*
  Isolation Forest (multivariate) run independently; each anomaly is flagged with
  whether both methods agree.
- **Trend**: linear slope + % change vs a matched prior window, classified
  against the series' own volatility (so "unusual" is calibrated per commodity,
  not a fixed threshold).

## Known limitations (honest, not hidden)

- All data is synthetic until real Agmarknet/e-NAM/weather credentials are added.
- `predict-price` beyond 1 day naively reuses the latest lag features rather than
  re-simulating them forward; for real multi-day horizons use `/forecast` instead.
- Models are per (commodity, market) pair and must be trained via `/api/v1/train`
  (or `train_all.py`) before `/predict-price` or `/market-insights` will return a
  prediction — `/predict-price` returns HTTP 404 with a clear message if untrained,
  it does not fabricate a number.
